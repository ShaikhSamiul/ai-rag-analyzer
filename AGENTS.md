## 1. Project Overview & Architecture Snapshot

The **AI-Powered RAG Document Analyzer** is a decoupled full-stack Retrieval-Augmented Generation (RAG) system:
* **Frontend:** React 19 SPA powered by Vite, providing file upload (drag & drop), cold-start monitoring, and a conversational chat interface.
* **Backend:** FastAPI (Python 3.11+) implementing document ingestion, text chunking, vectorization, and LCEL (LangChain Expression Language) question-answering pipelines.
* **Vector Store:** Pinecone serverless vector index (`rag-analyzer`) with multi-tenant data isolation using unique `session_id` namespaces.
* **LLM & Embeddings:** Google Gemini models (`gemini-embedding-001` generating **3072-dimensional** vector representations, `gemini-2.5-flash` for contextual synthesis).
* **Hosting:** Frontend deployed to Vercel; Backend deployed as a web service on Render (free tier with cold-start wake-up handling).

## 3. Critical Invariants & Rules for Agents

When making changes to this codebase, adhere strictly to the following requirements:

### A. Vector Dimension Consistency
* Pinecone index dimensions **must strictly match** the vector length generated by the embedding model.
* Active model: `models/gemini-embedding-001` generates **3072-dimensional** vectors.
* Pinecone index `rag-analyzer` is configured with **3072 dimensions** and **Cosine** similarity metric.
* Do not switch embedding models without verifying the Pinecone index configuration.

### B. Multi-Tenant Namespace Isolation
* Every document upload generates a client-side `session_id` (e.g. `session-<timestamp>-<hash>`).
* Ingestion (`PineconeVectorStore.from_documents`) and Retrieval (`PineconeVectorStore(..., namespace=request.session_id)`) **must always** be scoped to this namespace.
* Never query Pinecone across empty/default namespaces to prevent cross-user document leakage.

### C. CORS Configuration
* The backend configures `CORSMiddleware` supporting both production and local origins via `CORS_ORIGINS`.
* Defaults include `https://ai-rag-analyzer.vercel.app`, `http://localhost:5173`, and `http://127.0.0.1:5173`. Never remove local origins when refactoring.

### D. File Cleanup & Ephemeral Storage
* Uploaded files in `backend/temp_uploads/` are automatically deleted via a `finally` block in `/upload` after chunking and vectorization to prevent disk storage bloat.

### E. Environment Variable Security
* Never commit `.env` files or hardcode API keys in any code, documentation, or commit messages.
* When adding new configuration keys, update `backend/.env.example` and `frontend/.env.example`.

### F. Preserve Documentation & Code Intent
* Preserve existing code comments and docstrings.
* If refactoring an endpoint or component, maintain backward compatibility unless explicitly instructed.

## 4. Local Development & Testing Workflows

### Operating System: Windows (PowerShell)
* **Backend Run:**
  ```powershell
  cd backend
  .\venv\Scripts\Activate.ps1
  pip install -r requirements.txt
  uvicorn main:app --reload --host 127.0.0.1 --port 8000
  ```
* **Frontend Run:**
  ```powershell
  cd frontend
  npm install
  npm run dev
  ```
* **Linting:**
  ```powershell
  cd frontend
  npm run lint
  ```

## 5. Verification Checklist for AI Agent Changes

Before declaring any task or enhancement complete, verify:
1. [ ] **Syntax & Imports:** Ensure all new Python imports are declared in `backend/requirements.txt` and all NPM packages are saved to `frontend/package.json`.
2. [ ] **CORS Check:** Verify that local requests from the Vite dev server (`:5173`) reach the FastAPI backend (`:8000`) without CORS rejections.
3. [ ] **Error Handling:** Endpoints must return proper HTTP status codes (400 for invalid files, 404 for missing sessions, 500 for unexpected errors) with clear JSON detail messages.
4. [ ] **Type & Prop Safety:** React components must handle empty states, loading indicators, and error banners gracefully without breaking rendering.
